# Drawfree

**Abandoned (founder, Oct 2026).** The site is offline: both Cloudflare Workers were deleted by the Teardown workflow, the deploy and preview jobs are gone, and the repo is archived. What follows describes the code as it was left.

Storyboards you drag, not draw. A browser tool for building storyboard frames from full-body characters in the Open Peeps style. Users pick a body in the pose they need (standing, sitting, waist up), swap hair, faces and glasses, recolour skin, hair and clothes, flip a character to face left or right, and move, scale and rotate it. No drawing skill needed.

Stack: Vite, React 18, TypeScript (strict), Zustand. Static site on Cloudflare Workers. No accounts, free forever, no watermark.

## Commands

```
npm install
npm run dev              # Vite dev server
npm run build            # tsc --noEmit, then vite build into dist/
npm run lint             # Biome: no `any`, hook dependencies, unused code, a11y, console
npm run typecheck        # tsc --noEmit
npm test                 # Vitest + jsdom (unit, store, persistence, UI smoke)
npm run check            # tools/check.js on dist/: size budget, parts/rig/scenes stay pure
npm run ci               # what CI runs: lint, typecheck, test, build, check
npm run e2e              # Playwright: Chromium, WebKit, phone and iPad viewports (interaction + axe). Builds and serves dist itself
npm run e2e:install      # one-off: download the Chromium and WebKit browsers for Playwright
npm run sheet            # render a contact sheet of every part to art-sheet.png (use this to check art changes)
npx tsx tools/import-peeps.ts                 # regenerate src/parts/peeps/*.gen.ts from the Open Peeps pack in assets/open-peeps/
npx tsx tools/import-peeps.ts review out.png head/Bun ...   # numbered colour-region map, for editing REGIONS in the importer
npm run deploy:staging   # build + check + wrangler deploy --env staging (drawfree-staging)
npm run deploy           # same for production (drawfree). Ask before running; staging first
npm run deploy:preview   # wrangler versions upload to staging, no traffic change (CI does this per PR)
```

Run `npm run ci` before committing. Biome suppressions (`biome-ignore`) must carry a reason; there are a handful, all deliberate (pointer-only drag handles, a roving-tabindex group, the TypeScript 7 regex). Run `npm run sheet` and look at it after any art change. jsdom has no canvas, so PNG encoding is not covered by `npm test`: check it in a real browser (see Gotchas).

Hard rule: nothing in `src/parts`, `src/rig` or `src/scenes` may import React or touch the DOM. They take data in and return SVG strings out. `tools/check.js` enforces it. Biome bans `any`.

### Character model

A character is plain data from `newCharacter()`: part ids (`body`, `hair`, `face`, `glasses`, `facial`), colours (`skin`, `hairC`, `topC`, `botC`, `shoeC`, `hatC`) and placement (`x`, `y`, `s` scale, `r` rotation in degrees, `flip`). Items are `kind: 'char'` or `kind: 'prop'` (with `prop: <id>`). The SVG is regenerated from this data on every change. Never store SVG in state. The in-memory shape is the project file shape (spec data model).

### Coordinate space

- Local space: pelvis near (0,0), figure faces +x, ground line `GROUND` (189, in `rig/geometry.ts`), y grows down. The head art is anchored at (0,-212) in Open Peeps body space: the importer maps Open Peeps head space so the point between the eyes (head-local 309,296) lands on (13.5,-214) at scale 0.144. Every Open Peeps body is drawn in its art's space moved down `GROUND - box[3]` onto the ground line, with the head inside the same move.
- Left-facing is `scale(-1 1)` on the `.body` group. Position, rotation and scale sit on the outer `.item` group.

### No posable figure (founder's decision, Oct 2026)

Three attempts at a drag-to-pose figure were dropped: a hand-drawn figure (PR 13, "ugly"), Open Peeps art cut into a puppet (PR 18, shipped then rejected: the arms read as skinny and the joints as cut-outs), and a redraw of the bodies (PR 19, closed). Every character is now an Open Peeps body in the pose it was drawn in. Project files of version 2 and 3 that used the figure (`body: 'rig'`) load as `stand-shirt-3`, the body the puppet was cut from (see Project files). If posing comes back it should be a search over the 64 drawn poses, or AI generation as an experiment, not limbs on joints.

### Open Peeps parts (milestone 6)

Hairstyles (each includes the head), expressions, facial hair and glasses come from Open Peeps (CC0, `LICENSES.md`). `tools/import-peeps.ts` reads the pack from `assets/open-peeps/` (gitignored), maps every path into rig space, rounds to 0.1 and writes compact relative path data to `src/parts/peeps/*.gen.ts`. `src/parts/heads.ts` names them, tags them and sets picker order; it throws if an import adds or drops a part without a name. `peepSVG(art, {skin, hair, hat})` draws them.

- The pack is black and white: one white silhouette under black ink. Each layer has a kind: `s` skin, `h` hair colour, `a` hat colour, `w` white, `i` ink, or a fixed colour. White in a head is skin, in facial hair it is light hair, in glasses it is white.
- Light hair, hats and headbands are white in the pack too, so the importer splits the white into regions (`tools/peeps-regions.ts`: rasterise with resvg, flood fill, trace the chosen regions back to polygons grown 1.5 units so they hide under the ink). `REGIONS` in the importer lists which region of which head is hair or hat, by a seed point; `cuts` close ink gaps where hair strokes stop short of the face. `review` draws a numbered map with a 25-unit grid. The importer refuses a seed that lands in the face.
- Faces: every hole the ink fully encloses (eye whites, teeth) is filled white, or it would show the skin colour.
- Dark hair and dark garments are solid ink in the pack. The importer finds the solid parts of the ink (`thickInk`: erode by `ERODE` so strokes vanish, grow back by `REGROW` so an ink ring stays as the outline) and draws them over the ink in the hair colour (every head and beard; the hijab and wide-brim hat in the hat colour), the top colour (waist-up bodies, except `BUST_KEEP_INK`), or, for full bodies, by `FAMILIES`: siblings with the same geometry whose light garment is labelled say which solid ink is top, trousers or shoes. Cycling and Legs crossed have no light sibling, so their trousers stay black. `HAIRC` starts with black (the default). Bear (a shaggy beard-and-hair mass with no drawn face edge) stays skin-coloured.
- Hats are hairstyles (Beanie, Wide-brim hat, Turban, Hijab), coloured by `hatC`. There is no hat slot and no neckwear any more (Open Peeps has none). Project files are version 4 (see Project files); `MIGRATIONS[1]` maps the old head ids (crop, curly, grin, round, beard, beanie...) to the Peeps ones, and the legacy autosave reader does the same.

### Bodies

`body` is an Open Peeps body: 23 standing (`stand-*`), 11 sitting (`sit-*`, the bike and wheelchair included) and 30 waist up (`bust-*`). `parts/bodies.ts` names and tags them. Each comes dressed and in its own pose; `topC`, `botC` and `shoeC` recolour its clothes.

- **Art loads on demand.** The bodies are about 176 KB gzipped, a separate chunk: `loadBodyArt()` fetches it (main.tsx calls `loadArt` at start, every export awaits it), `bodyArt(id)` returns it once in. Until then a character shows its head only. The store's `art` counter bumps on arrival; `ItemView`, the frame strip, the Overlay and the picker thumbnails (`bodyArtVersion()` in the cache key) redraw on it. `tools/check.js` fails the build if the art lands in the first-load bundle. Tests load it in `src/test/setup.ts`.
- **Placement.** The importer writes each body's bounds (`bodies.box.gen.ts`, in the main bundle). `charSVG` moves the body and its head down by `GROUND - box[3]` so every body stands on the ground line (`GROUND = 189`); a waist-up body rests its bottom edge there and has no shadow. `charBounds` sizes the click and focus area from the same bounds.
- **Colour.** Skin, top, bottom and shoe regions of every body were labelled by hand in `REGIONS` (tools/import-peeps.ts) and checked on a coloured contact sheet. White soles, laces, prosthetic legs, the bike and the wheelchair stay white. Black garments are ink, as in Open Peeps.
- **New characters** get `NEW_BODY` (stand-resting-1); `newCharacter()` defaults to `DEFAULT_BODY` (stand-shirt-3). Shuffle keeps the kind of body (standing, sitting, waist up).
- **Picker.** The Body tab holds the Standing and Sitting bodies and the Tops tab the 30 waist-up ones (cropped at the chest, so they cannot go on legs), each thumbnail framed on its own (`viewOf` in `ui/sections.ts`). Head thumbnails (hair, expressions, extras) are drawn on `DEFAULT_BODY`, whose head position `HEADV` is framed for. The Clothes tab holds the top, bottom and shoe colours.

### Adding a part

Add an entry to the right list (for example `PROPS` in `src/parts/props.ts`) with `id`, `name`, `tags: tags('space separated words')` and what its type in `types.ts` asks for, using `INK` outlines (stroke `W`, 2.3, matched to the Open Peeps ink). A new category also needs a section in `src/ui/sections.ts` (and a slot in `PART_LISTS` if it is a character slot). Thumbnails, search and the picker UI follow from that. Run `npm test` (it draws every part with every palette colour and checks the SVG parses) and `npm run sheet`.

## State and editor behaviour to preserve

- **Immutable state.** Every action builds new frames and items; never edit in place. `React.memo` on `ItemView` and cheap undo both depend on it. Past snapshots are plain references.
- **History.** `snap()` pushes one undo step. Call it once before a mutation. For drags it runs only after the pointer has moved 3px (move) or at all (other drags), so a click never makes an undo step. Typed text (note, project name) makes no step per keystroke; a bubble's text snaps once on focus.
- **Drags.** `editor/interactions.ts` keeps the drag session in a ref with `pointermove`/`pointerup` listeners on `window`. Never attach drag state to elements: the stage re-renders on every change.
- **Joint dragging** uses the inverse of the `.body` group's `getScreenCTM()`, so joints land on the pointer after flip, rotation and scale.
- The selection box turns with the item (see roadmap item 5). The Overlay re-measures in `useLayoutEffect` after every render.
- Thumbnails (picker and frame strip) are `<img>` data URLs (`svgImgSrc`), not inline SVG: far fewer DOM nodes, and their text stays out of the accessibility tree. The frame strip's order and current ring follow the live list; only the thumbnail art is deferred.
- The rotate handle sits above the (turned) selection box, else below it if that stays inside the stage, else beside it. (On phones the toolbar sits under the stage, so a handle below the box used to be hidden behind it.)
- Hit areas exist only in the editor. `itemSVG` (export, thumbnails) emits no editor chrome.
- The ground shadow shows only when rotation is under 8 degrees.
- The picker and frame strip use `useDeferredValue`, so they catch up when a drag settles instead of re-rendering per pointer move. Thumbnails are cached in `ui/thumbs.ts` by section, part and the character's look.
- Dialogs use `ui/Dialog.tsx` (focus moves in, to the element marked `data-autofocus` or the first control; Tab is trapped, Esc and backdrop close, focus returns). Never use `alert`, `confirm` or `prompt`: use the toast and dialogs.
- **Markup from strings.** Art is SVG strings injected with `svgMarkup()` (`ui/markup.ts`, the only place `dangerouslySetInnerHTML` is used). Only pass strings built by the pure part, rig and scene functions, which escape user text with `esc()`. Never pass user input, file contents or anything not drawn by our own code.
- Autosave (`state/persist.ts`): key `drawfree.v1`, debounced 500 ms, flushed on `pagehide` and when hidden, never throws, warns once if storage is blocked. It reads the old prototype shape (`type`/`kind` items) and the older `inkframe.v1` key.

## Export

- **Frame**: SVG, or PNG at 1x/2x/3x, optional transparent background (`export/frame.ts`, `svg.ts`, `png.ts`).
- **Board PNG strip** (`board.ts`): every frame drawn onto one canvas in a grid (1 to 4 columns, 480/720/960 px frames) with numbered captions and optional notes. The canvas text uses Figtree, so any script works. `layout.ts` shrinks the frames when the image would pass the browser's canvas limits (16 million pixels, the Safari cap) and throws if even tiny frames cannot fit.
- **Board PDF** (`pdf.ts`): A4 or Letter, landscape or portrait, one frame per page or a 2 or 3 per row contact sheet. Frames are PNG images (2x), notes are real text. pdf-lib's built-in Helvetica covers Latin-1 only, so other characters (emoji, CJK, Arabic) become `?` and the toast says how many. Fixing that needs an embedded font (`@pdf-lib/fontkit` plus a font file, also loaded on demand).
- **pdf-lib is a dynamic import** and a separate 172 KB chunk. `tools/check.js` fails the build if it ever lands in the first-load bundle. Keep `import('pdf-lib')` inside `buildPdf`.
- All layout math is pure (`export/layout.ts`) and tested in Node. `buildPdf` takes the frame renderer as an argument, so its tests run real pdf-lib without a canvas. The canvas parts (`board.ts`, `png.ts`) are only checked in a real browser.
- The export dialog remembers its choices in localStorage (`drawfree.export`), guarded for blocked storage.

## Frames

Add, duplicate, delete, reorder, and a note per frame. Reordering (`moveFrame`) works three ways: drag a thumbnail (mouse and pen; `FrameStrip` keeps the session in a ref with window listeners, like the stage), the Move earlier and Move later buttons, and Alt+Arrow on a focused thumbnail. Touch drags are left to the strip to scroll, so touch users use the buttons. A move is one undo step, the current frame stays current, and a toast announces it. The strip compares the current frame by id, not by index, because the thumbnails are a deferred value.

## Project files

`export/project.ts` is the only door for data from outside (opened files, localStorage): `parseProject`, `parseProjectObject`, `cleanFrames`. It repairs rather than rejects: unknown part ids fall back to the section's first part, bad colours to defaults, numbers are clamped, XML-illegal characters stripped, unknown props dropped (counted, shown in a toast). Files from a newer version are refused. To change the format: bump `PROJECT_VERSION` and add `MIGRATIONS[oldVersion]`. Version 4 (`MIGRATIONS[3]`, `framesV3toV4`) dropped the posable figure: a character on it (`body: 'rig'`, or no `body` at all in older files) becomes `DEFAULT_BODY`, and its `top`, `bottom`, `shoes` and `pose` fields go (its colours stay). Version 3 only changed the figure's clothes, so `MIGRATIONS[2]` just bumps the number. The legacy autosave reader runs the same steps. In a current file a missing or unknown body is repaired like any part id. New character fields go in `PART_LISTS`/`COLOR_SLOTS` handling in `cleanItem`. File names: `<project-name>-frame-<n>.<ext>`, `<project-name>.drawfree.json`.

## Gotchas

- Aspect ratio: v1 is 16:9 only, by the founder's decision. The `aspect` field stays in the project file and is preserved, but nothing reads it.
- Scene line colour switches by background luminance. Character outlines are always near-black, so dark backgrounds make them hard to see. Keep backgrounds light unless outlines become themeable.
- PNG export draws the SVG through an `<img>`, which cannot use the page's web fonts, so speech-bubble text falls back to the system font in PNGs until the fonts are self-hosted and embedded. The root `<svg>` needs explicit `width`/`height` for Safari and Firefox. Not yet tested in Safari or Firefox.
- The standalone page loads Figtree and Bricolage Grotesque from Google Fonts.
- In Playwright, `boundingBox()` of an SVG element includes its stroke width but `getBoundingClientRect()` (what the app measures) does not; when comparing against the selection box, measure with `getBoundingClientRect` in `page.evaluate`.
- jsdom stubs (`src/test/setup.ts`) fake `getScreenCTM`, `DOMPoint` and layout, so tests prove the logic, not the geometry. Geometry (drag lands on the pointer, selection box fits) was checked in a real browser.
- The old Claude artifact build (`dist/artifact.html`) is gone with the vanilla build. Downloads are blocked inside Claude's artifact viewer; Copy SVG (with its manual-copy dialog) is the fallback.
- TypeScript 7 rejects some regex literals the older compiler accepted; `XML_ILLEGAL` is built with `new RegExp(string)` for that reason.
- Linting is Biome, not ESLint: `typescript-eslint` does not support TypeScript 7 yet (peer range stops below 6.1). Revisit if that changes; do not force the install.
